# LIC Stack and File Provenance

This guide explains what tech is in this repo, why it exists, and whether key files are generated by tools or manually authored by you/the team.

## Stack used in this project

- `Next.js` (App Router) + `React` + `TypeScript` for the web app.
- `Clerk` for authentication (sign in, sessions, user identity).
- `PostgreSQL` as the relational database.
- `Neon` as the serverless Postgres hosting platform.
- `Prisma` as ORM + migration + typed DB client.
- `Biome` for lint/format.
- `Vitest` for tests.
- `CSS Modules` as primary styling system (Tailwind still installed for compatibility).
- `Radix UI` primitives in `src/components/ui`.

## Generated vs manual files (important)

Use this rule of thumb:

- **Generated by install/build tools**: can be regenerated, should rarely be hand-edited.
- **Manual source files**: your application logic, should be reviewed and versioned carefully.

### Usually generated (tool-managed)

- `next-env.d.ts` (Next.js generated type helper).
- `.next/**` (build/dev artifacts).
- `node_modules/**` (package install output).
- `pnpm-lock.yaml` (package resolution lockfile, managed by package manager).
- `prisma/migrations/*/migration.sql` (generated by Prisma migration engine after schema changes).
- `prisma/migration_lock.toml` (generated/managed by Prisma migrate).

### Usually manual (application source)

- `prisma/schema.prisma` (your DB model source of truth).
- `prisma/seed.ts` (your custom seed script).
- `src/**` app code.
- `docs/**` documentation.
- `.agents/skills/**` if created in-repo for local agent workflows.

## If `.agents` was pushed to GitHub by accident

Immediate containment (applies now):

1. Add `/.agents/` to `.gitignore` (done).
2. Remove tracked files while keeping local copies:
   - `git rm -r --cached .agents`
3. Commit and push the removal.

History cleanup options (if sensitive data was ever committed):

- Preferred: `git filter-repo --path .agents --invert-paths`
- Alternative: BFG Repo-Cleaner

Important:

- History rewrite requires force-push and team coordination.
- If secrets were present, rotate them even after cleanup.

### Where was `prisma/migrations/20260412170000_init_portal_rbac/migration.sql` sourced from?

- This file is generated by Prisma when you run `prisma migrate dev` after editing `prisma/schema.prisma`.
- Source chain is:
  1. Manual schema edit in `prisma/schema.prisma`
  2. Prisma diff engine computes SQL
  3. Prisma writes migration folder + `migration.sql`

### Where was `prisma/schema.prisma` sourced from?

- Manual file created for this project's data model.
- Prisma CLI scaffolds an initial template when `prisma init` is run, then you evolve it manually.

### Where was `prisma/seed.ts` sourced from?

- Manual seed script written for project onboarding/dev bootstrap.
- Triggered via `pnpm prisma:seed` (`package.json` script).

## Media performance note: `public/assets/Licskylinefootage.mp4`

- Current file size is about **15.99 MB**.
- For a landing hero background, this is heavy and will likely hurt mobile performance and Core Web Vitals (especially LCP and total transfer size).

Weighted options:

| Option | Perf impact | Visual quality | Dev effort | Cost impact | Recommendation |
|---|---:|---:|---:|---:|---|
| Keep current MP4 as-is | 1/5 | 5/5 | 5/5 | 5/5 | Not recommended |
| Re-encode MP4 only (H.264, lower bitrate) | 3/5 | 4/5 | 4/5 | 5/5 | Good immediate step |
| Add WebM + MP4 fallback + poster + lazy load | 5/5 | 4/5 | 3/5 | 4/5 | Best balance now |
| Replace with static image on mobile / reduced-data users | 5/5 | 3/5 | 3/5 | 5/5 | Strong complement |
| Adaptive streaming pipeline (HLS) | 5/5 | 5/5 | 2/5 | 2/5 | Overkill for now |

Recommended immediate action plan:

1. Encode `WebM` (primary) + optimized `MP4` fallback.
2. Add `poster` image and reserve dimensions to avoid layout shift.
3. Use `preload="metadata"` and lazy-start playback.
4. Disable background video for reduced-motion and small viewports.
5. Verify with Lighthouse + WebPageTest before/after.
